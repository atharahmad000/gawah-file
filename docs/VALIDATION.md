# Validation record

Environment: Windows, Python 3.12. Dependencies are recorded in `requirements-lock.txt`. All customer data is synthetic. Offline mode is the default.

Latest full-suite result after the documentation and integrity review: **27 passed in 173.71 seconds** on Windows/Python 3.12. The focused writer, integrity and linked-wallet checks also passed: **9 passed in 38.64 seconds**. Runtime varies with the machine and concurrent work; these timings are observations, not performance targets.

JSON/Markdown exports for all six fraud cases, an additional A6 care pack and the generated graph were rebuilt successfully using isolated temporary data. The three SVG illustrations were rendered in headless Chrome for visual inspection. The repository checker passed for publishable files, including relative file links and obvious credential patterns.

Earlier validation also exercised the gate, checkpoint-fork and command-line review demos, and both desks through the local Studio API. Those checks are distinguished below from the suite rerun for this review.

The implementation was built in the phase order from the two Word documents: schema and seeds, repository story checks, handbook retrieval, load-only graph, deterministic packs, signature gate, linked-wallet subgraph, guarded optional writer, risk rules, memory, desk configurations and goldens.

Verified checks:

- All six planted SQL stories; bound identifiers and foreign-key enforcement.
- Whole-page retrieval, negative-control ranking and weak-query rejection.
- All six golden alerts pause with valid citations and expected recommendations.
- Unsigned resumes are refused; explicit signed overrides produce an atomic audit record.
- Approval replay is idempotent; a different replay decision or changed pack is refused.
- A3 produces separate Sara and Nadia evidence memos through Send/subgraph execution.
- Both linked-wallet memos survive in the saved SQL pack, not just intermediate graph state.
- A4 and A6 do not propose freeze; A5 pauses despite the PKR 400 amount.
- Feature cutoffs exclude later transactions; actual first credit is distinguished from later receipts.
- Stored case memory survives a new graph instance and remains customer scoped.
- Model output cannot substitute wallet ids, amounts or recommendations; invalid citations fall back safely.
- A model candidate cannot remove policy support still used by the retained rationale.
- Audit provenance uses the saved proposal and alert cutoff even if duplicate state fields are edited.
- Both desk configurations ran through the local Studio API: paused, refused unsigned resume, accepted scripted signed watch.

Run `python -m pytest -q -p no:langsmith` for the complete suite and `python -m pytest evals/test_goldens.py -q -p no:langsmith` for the project's acceptance gate. Test databases and indexes are isolated under pytest temporary directories.

The hosted Studio browser UI and live paid chat-model response were not visually/provider tested. The local server and its HTTP workflow were exercised. No video recording, deployment, real financial integration or authenticated multi-user sign-off is claimed.

GitHub preparation adds repository checks and an offline CI matrix for Ubuntu/Python 3.11 and 3.12 and Windows/Python 3.12. Hosted CI results are pending the first push. Local environments, secrets, databases and checkpoint files are excluded from version control.

## Review findings addressed

Three findings affected the evidence record. A3's entity memos previously lived in graph state without being included in the saved pack; they are now part of `linked_evidence`. The optional writer could narrow citations while retaining a rationale that still referenced the omitted clause; the complete deterministic citation set and quotes now remain intact. Approval audit details previously read the proposal and cutoff from editable duplicate state fields; they now read the saved pack and operational alert.

Each behavior has a regression assertion. The presentation changes add explanatory SVGs, case studies, a setup walkthrough and a Markdown renderer with explicit pending/approved-draft status. No external financial execution was introduced.

## What passing means

The suite establishes expected behavior on controlled synthetic inputs. It does not establish real-world fraud precision, recall, regulatory compliance, adversarial security or production readiness. The label fixtures are not an independent evaluation dataset. Local signature fields do not prove officer identity, and the optional online headline remains prose requiring review even when structured facts are preserved.

The full suite can be rerun without clearing the local demo database. Exported examples likewise use disposable data. For interactive verification, follow [getting started](GETTING_STARTED.md); for a presentation, use [the walkthrough](DEMO.md).
